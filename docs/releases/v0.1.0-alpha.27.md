Apps now carry their own copy of `izzy`, so it runs with nothing on your PATH, and `izzy audit` checks a page's accessibility.

## CLI

- **izzy as a tool of the app.** Every starter and kit writes `.config/dotnet-tools.json` with IzzyBlazor.Cli at the version of the app's IzzyBlazor package, and `izzy new` restores it. In the app's folder, `dotnet izzy <command>` then works without `~/.dotnet/tools` on the PATH, and everyone who clones the app gets the same izzy after `dotnet tool restore`.
- **`izzy init` adds the same manifest** to an app you have. An app that already has a tool manifest keeps its other tools: izzy is added to it, or its version there is changed to the library's. The change shows in `--dry-run`, `--diff` and `--json` like any other.
- **`izzy agent` and `--mcp` write the server as `dotnet izzy mcp`** in an app with the manifest, so a coding agent needs nothing on the PATH either. Apps without it keep `izzy mcp`.
- In an app with the manifest, the commands izzy tells you to run are written `dotnet izzy …`.
- **`izzy audit <url>`** checks a page with axe-core in the Chrome, Edge or Chromium already on your machine, at 1440 and 375 pixels, in light and dark. It prints each rule that failed and writes `report.md` and `results.json` to `.izzy/audit/`. `--run` starts the project's app for the audit and stops it after. `--fail-on any` ends with exit code 5 when there are findings. Also `--sizes`, `--schemes`, `--out`, `--format`, `--json` and `--browser` (or `IZZY_BROWSER`). One page is free; several pages in one run come with IzzyBlazor Pro.
- **`izzy add component`:** when a member of your page has the name of a type in the example's own file (a page with an `Orders` list, and Table's `Orders` class), the example reaches the type through `@using Orders2 = …`. It was a warning asking you to rename your member.
- `izzy add component` gives a local in the example's `@{ }` block a number when the page has one by that name, so the same example can go on a page twice.
- `izzy add component --overwrite` is an error: the option did nothing there.
- An option takes a negative number as its value: `izzy set … --min -5`. It needed `--min=-5`.
- A brace in the text of an element written inside `@code` (a render fragment) no longer ends the block for izzy.
- izzy refuses to write through a link inside the project that leads out of it. Reading through one still works.
- izzy finds `dotnet` from the one that runs it, then `DOTNET_ROOT`, then the runtime's folder, before the PATH. When it can't start `dotnet`, it says so in a sentence and exits with 1; it was a stack trace.
