A small fix release: a dialog opened from a link no longer shifts the page, and the dialog's close button sits in the corner with a larger X. No API changes.

## Fixed

- **Opening a dialog from a link** (`?dialog=`, or anything else that locks the page and arrives by enhanced navigation) no longer shifts the page sideways by the scrollbar's width. Enhanced navigation was dropping the width that pads the locked page in place of its scrollbar; it's now kept.

## Overlays

- **Dialog's close button** sits in the corner, 0.5rem from the top and end edges, with a 1.25rem icon (it was 1rem, centered on the title's line, and looked small and low). A title that wraps no longer puts the button halfway down its two lines. The title, body and header height are unchanged. Drawers share the header, so theirs moves too.

## Docs site

- A troubleshooting article, "Interactive parts stop responding in production": a circuit lives on the server that started it, so behind a load balancer each reader has to stay on one server. It covers the 404 "No Connection with that ID" in the console, sticky sessions, Azure SignalR Service, running one server (Fly.io's `--ha=false`) and WebSockets through a proxy. Render modes links it.
- The site runs on one machine again, so Live examples, such as Slider's "Following the value live", keep their connection.
