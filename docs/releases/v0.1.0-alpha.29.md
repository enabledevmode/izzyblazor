`izzy audit` checks a whole site in one run and reliably looks inside iframes, `izzy inspect` gives an expression as its C#, and a new article counts what a page costs in each render mode.

## CLI

- **`izzy audit --site <url>` audits a whole site (Pro).** The pages are those the site's `sitemap.xml` lists, else those its links lead to. An address with a path keeps the audit inside it, and `izzy audit --run --site` is the whole app. `--max-pages` (500) is the limit.
- **`--urls <file>`** audits a list of addresses, one a line (Pro).
- **`--cookie name=value`** goes with every request, for pages behind a sign-in. While izzy looks for a site's pages, the cookie is sent only to the site being audited.
- A run of 24 loads or more is shared between up to three browsers. A report of many pages lists each page once.
- **Iframes are audited on every run.** The browser sometimes handed the audit an iframe's first, empty document, so an iframe's findings came and went between runs. A frame from another site and a frame inside a shadow root are audited too.
- **A selector in `.izzy/audit.json` finds an element inside an iframe,** and what the iframe is inside counts as around the element. So `demoPages` can name the element that holds an example drawn in an iframe.
- `/docs/` and `/docs` are one page for a finding's id and for a baseline.
- A page that has an `axe` of its own, or an element with `id="axe"`, is audited; it failed to open.
- A browser that dies in a run shared between browsers ends the run with a message.
- **Breaking, for a front end: `izzy inspect` gives an attribute's `expression` as the C# it is written as,** such as `new Responsive<int>() { Base = 2 }` or `_size`, without Razor's `@` and the parentheses around the whole. It is null beside a plain `value`. It was `true` or `false`.
- `izzy inspect` reads `@(2)` as 2 and `@(CardVariant.Outline)` as Outline, as it does without the parentheses. An email address or `@@` in text is a plain value.

## Site

- **A crawler can't walk the examples' states.** Every page gives its reader a pass, the `ib-reader` cookie: a random number that lasts 12 hours and isn't logged or tied to you. A page with a query string, or an example's frame in one of its states, renders only for a request that carries it. The privacy page names the cookie.
- The whole docs site is audited: 543 pages at two widths, in light and dark, with no real findings. The cards in the AppShell, AppSidebar and SiteNav page examples are `h2` under the page's `h1`, and the Rich Text Editor's custom colors example puts its colors on the heading, where they pass in light and dark.
