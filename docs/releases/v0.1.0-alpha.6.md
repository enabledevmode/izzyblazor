Forms can lay their fields out in columns: `<Form Columns="2">`, sized by the form's own width so it fits a dialog too, with `ColSpan` on any field. `NumberInput` is renamed `NumberField`, to match `TextField` and the other fields that render their own label. Messages you set with `ErrorMessage` on your model's attributes now show in the browser's checks before posting, too.

## Changed (check when you update)

- **`NumberInput` is now `NumberField`.** Rename the tag in your pages. Razor doesn't fail on an unknown tag: an old `<NumberInput>` builds with warning RZ10012 and renders a stray `<NumberInput>` element with no field, so search for `NumberInput` when you update. Its parameters, CSS and `IzzyText` strings are unchanged.

- **`ColSpan` moved from `GridItem` to every component.** `<GridItem ColSpan="…">` works as before; its rendered span changed (`span min(2, …)`), which only tests that compare markup notice.

## New

- **Form columns.** `Columns` on `Form` (1 to 4, default 1) lays the fields out in up to that many columns, sized by the form's own width rather than the screen's: two from 32rem, three from 48rem, four from 64rem. Fields take one column; text, `FormErrors`, rows of buttons and `Fieldset`s take the row. `Fieldset` takes `Columns` too.
- **`ReadOnly` and `Disabled` on `Form`**, for every field in it: `<Form ReadOnly="!editing">` shows a record that still posts; `Disabled` posts nothing. Buttons are left alone.
- **`RequiredMark` on `Form`**: `Required` (an asterisk on required fields, the default), `Optional` ("(optional)" on the fields that aren't required) or `None`. New `IzzyText.Optional` ("(optional)").
- **`FormActions`**, the row of buttons at the end of a form: the whole row, buttons at the end (`Justify` moves them). Last in a form that fills a `Dialog` or `Drawer`, it becomes the dialog's footer, like `DialogActions`, and its buttons still submit the form.
- **`ColSpan` on every component**, fields included: `ColSpan="2"`, or `ColSpan="GridSpan.Full"` for the whole row. In a form it never spans more columns than are shown, so a form that narrows to one column needs no breakpoints. `NewRow` starts an item on a new row.

- **The model's error messages before posting.** When `[Required]`, `[StringLength]`, `[MinLength]`, `[MaxLength]`, `[Range]`, `[EmailAddress]` or `[Url]` has an `ErrorMessage` (or a resource message), the browser's own check shows it in place of its built-in text ("Please fill out this field"), so the message before posting matches the one after. Attributes with the default message keep the browser's text, as does every field with JavaScript off. To word one form differently, set `data-ib-required="…"` (or `data-ib-length`, `data-ib-range`, `data-ib-type`) on the field.

## Fixed

- **`ReadOnly` on `Select`, `Combobox`, `MultiSelect`, `Checkbox`, `Switch`, `RadioGroup`, `SegmentedControl` and `CheckboxGroup`** did nothing: the value could still be changed. These are now disabled while read-only (styled as values, not as unavailable) and post their values from hidden inputs, as `Slider` and `ColorPicker` already did.

## Size

The script grows by about 210 bytes gzipped.
