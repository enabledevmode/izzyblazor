Forms get columns (`<Form Columns="2">`, sized by the form's own width so it fits a dialog too), `ReadOnly`, `Disabled` and `RequiredMark` for every field, a `FormActions` button row, and tabs that show their errors. `NumberInput` is renamed `NumberField`. Read-only selects, checkboxes and radios are now really read-only. The script every page loads is a third smaller. Check the first section when you update.

## Changed (check when you update)

- **`NumberInput` is now `NumberField`.** Rename the tag in your pages. Razor doesn't fail on an unknown tag: an old `<NumberInput>` builds with warning RZ10012 and renders a stray `<NumberInput>` element with no field, so search for `NumberInput` when you update. Its parameters, CSS and `IzzyText` strings are unchanged.
- **Read-only choices are read-only, not ignored.** `ReadOnly` on `Select`, `Combobox`, `MultiSelect`, `Checkbox`, `Switch`, `RadioGroup`, `SegmentedControl` and `CheckboxGroup` used to do nothing: the value could still be changed. Now a read-only `Select`, `Combobox` or `MultiSelect` shows its value in a read-only text field, and the checkboxes and radios stay focusable with `aria-readonly` and don't change (without JavaScript they're disabled). A read-only `Slider` (which was disabled) works the same way as the radios. They post their values from hidden inputs, and the boxes and radios themselves sit outside the form (`form=""`). Check pages that set `ReadOnly` on these and expected them to stay editable.
- **New item parameters `ColSpan` and `NewRow` on every component.** A component of your own that inherits from an IzzyBlazor component (`Box`, `LayoutItemBase`, `FieldBase<T>`) and declares its own `ColSpan` or `NewRow` parameter now throws when it renders: Blazor doesn't allow two parameters with one name. Rename yours, or use the inherited one.
- **`ColSpan` moved from `GridItem` to every component.** `<GridItem ColSpan="…">` works as before; its rendered span changed (`span min(2, …)`), which only tests that compare markup notice.
- **Tabs in a form, with JavaScript off, show every panel** in order, each under its tab's label, instead of tabs: the browser's own check before posting can't point at a field in a hidden panel. Tabs outside forms, and every tab with JavaScript, are unchanged.
- **A `Slider` on a static page no longer renders `aria-valuetext`**: without script it couldn't follow the thumb. The script sets it, so screen readers hear the formatted value with JavaScript and the plain number without it.

## New

- **Form columns.** `Columns` on `Form` (1 to 4, default 1) lays the fields out in up to that many columns, sized by the form's own width rather than the screen's: two from 32rem, three from 48rem, four from 64rem. Fields take one column; text, `FormErrors`, rows of buttons and `Fieldset`s take the row. `Fieldset` takes `Columns` too. A form with columns fills its parent's width; `Width` or `Basis` sizes it.
- **`ColSpan` and `NewRow` on every component**, fields included: `ColSpan="2"`, or `ColSpan="GridSpan.Full"` for the whole row. In a form it never spans more columns than are shown, so a form that narrows to one column needs no breakpoints. `NewRow` starts an item on a new row.
- **`ReadOnly` and `Disabled` on `Form`**, for every field in it: `<Form ReadOnly="!editing">` shows a record that still posts; `Disabled` posts nothing. Buttons are left alone.
- **`RequiredMark` on `Form`**: `Required` (an asterisk on required fields, the default), `Optional` ("(optional)" on the fields that aren't required) or `None`. New `IzzyText.Optional` ("(optional)").
- **`FormActions`**, the row of buttons at the end of a form: the whole row, buttons at the end (`Justify` moves them). Last in a form that fills a `Dialog` or `Drawer`, it becomes the dialog's footer, like `DialogActions`, and its buttons still submit the form.
- **Tabs in a form** show how many errors each tab's fields have, read out with the tab's name. After a submit that fails, the first tab with errors opens (unless the open one has some), and the browser's own check before posting opens the tab of the field it points at. Only a submit switches tabs, never typing. Fields in nested tabs count toward the outer tab too. New `IzzyText` strings `OneError` ("1 error") and `ErrorCount` ("{0} errors").
- **The model's error messages before posting.** When `[Required]`, `[StringLength]`, `[MinLength]`, `[MaxLength]`, `[Range]`, `[EmailAddress]` or `[Url]` has an `ErrorMessage` (or a resource message), the browser's own check shows it in place of its built-in text ("Please fill out this field"), so the message before posting matches the one after. Attributes with the default message keep the browser's text, as does every field with JavaScript off. To word one form differently, set `data-ib-required="…"` (or `data-ib-length`, `data-ib-range`, `data-ib-type`) on the field.

## Fixed

- Without JavaScript, a `MultiSelect` (a list box until the script runs) no longer shows a dropdown chevron.
- Without JavaScript, a password field no longer keeps empty room for the show-password button, so Edge's own button sits at the edge. With JavaScript, Edge's button is hidden while IzzyBlazor's shows, so there's only one.
- Without JavaScript, a `NumberField` with steppers shows the browser's own spin buttons, so a mouse can still step the value (`StepButtons.None` shows neither).
- Without JavaScript, a `Slider`'s fill and value text no longer stay where the page loaded while the thumb moves: Chrome and Safari show a plain track and no value text (Firefox keeps its own fill).
- A `ColorPicker` that is both `Disabled` and `ReadOnly` no longer posts its value.

## Size

The script every page loads drops from about 15.2 KB to 10.3 KB gzipped. The code for `Combobox`, `MultiSelect`, `Table`, `FilterForm`, `FileUpload`, `ColorPicker`, `VideoEmbed`, `Code` and toasts now loads only on pages that have one, from its own file beside the module (`_content/IzzyBlazor.Core/elements/`), and a file that fails to load is tried again. Until it loads, which on a first visit takes one small request, those components show their server-rendered markup, as with JavaScript off. Nothing changes in your app: Blazor still loads one module, and it fetches the rest itself.
